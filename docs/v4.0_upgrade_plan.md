## 2. 核心问题诊断（Critical Issues）

### C-1：HybridizationWindow 主线程同步阻塞 — UI 假死

**严重性**：Critical（最高优先级）

**位置**：`ui/hybridization_win.py:315-330`

**问题**：`_generate_plot()` 在主线程中同步调用 `_parse_fragment()` → `DataLoader.load_spin_all()`。对于 100MB+ 的 vasprun.xml，pymatgen 解析耗时 3-10 秒，期间整个界面完全冻结。

与 MainWindow 不同——MainWindow 已通过 `CalculationWorker(QThread)` 将解析移至后台，但 HybridizationWindow 完全没有异步处理。

```python
# 当前代码 — 主线程同步执行（卡死来源）
def _generate_plot(self):
    try:
        e1, rho1_up, rho1_dn, orbs1, label1 = self._parse_fragment(self.frag1)  # 阻塞！
        e2, rho2_up, rho2_dn, orbs2, label2 = self._parse_fragment(self.frag2)  # 阻塞！
    except ...
```

**影响**：用户每次点击"Generate Plot"、切换主题、调整 X/Y 范围都会触发完整文件重新解析，界面假死数秒。

### C-2：HybridizationWindow 无解析缓存 — 重复 I/O

**严重性**：Critical

**位置**：`ui/hybridization_win.py:281-313`

**问题**：`_parse_fragment()` 每次都调用 `DataLoader.load_spin_all()` 重新读取和解析文件。`_on_theme_changed()` 直接调用 `_generate_plot()`，意味着切换颜色主题也会触发两次完整的文件解析。

同时，`AppState.parsed_cache` 中已经缓存了相同文件的解析结果，但 HybridizationWindow 完全不使用这份共享缓存。

```python
# 当前代码 — 主题变更触发重新解析
def _on_theme_changed(self):
    if self._has_plot_data:
        self._generate_plot()   # 重新解析两个文件，仅为了改颜色
```

**影响**：主题/范围调整的响应时间 = 2 × 文件解析时间，而非接近 0ms。

### C-3：God Class 违背 SRP — 544 行上帝类

**严重性**：High

**位置**：`ui/hybridization_win.py` 全文 + `ui/main_window.py:30-133`（CalculationWorker 内嵌）

**问题**：
- `HybridizationWindow` 单类承担了 UI 构建、文件解析、数据过滤、画图渲染、CSV 导出、PNG 导出共 6 项职责
- `CalculationWorker` 被直接定义在 `main_window.py` 内部，混淆了 UI 层与业务逻辑层的边界
- `draw_pdos()`（`pdos_chart.py:102-218`）单方法 218 行，自旋/非自旋分支高度重复

### C-4：能量对齐数据契约不一致

**严重性**：High

**位置**：`main_window.py:90` vs `calculator.py:41` vs `pdos_chart.py:187`

**问题**：`calc_metrics` 文档声明 `energy` 为"raw values"，内部执行 `e = energy - ef`。但缓存存储的是已对齐能量 `e_aligned = energy - ef`，后续调用以 `ef=0.0` 适配：

```python
# main_window.py:90 — 缓存已对齐能量
e_aligned = energy - ef
parsed_cache[label] = {"energy": e_aligned, ...}

# pdos_chart.py:187 — 用 ef=0.0 兼容已对齐数据
calc_metrics(e, rho_total_d, ef=0.0, ...)  # 隐式约定
```

**影响**：任何新接入方（CLI、测试、插件）必须知道传入的是"原始能量"还是"已对齐能量"，否则 `ef` 被重复减去。

### C-5：LRU 按文件数限流 — OOM 隐患

**严重性**：High

**位置**：`models/app_state.py:12` + `core/parsers/common.py:121`

**问题**：
1. `LRUCache(maxsize=20)` 按文件数淘汰，不估算内存。20 个上千原子体系的 PDOS 矩阵可消耗数 GB 内存
2. `_detect_cache`（`common.py:121`）是无限增长的 `dict`，无任何淘汰机制

### C-6：DataLoader if/elif 违反开闭原则

**严重性**：Medium

**位置**：`core/loader.py:57-62`

**问题**：新增解析格式（CASTEP、CP2K、QE）需要修改 `load()` 方法体，违反 OCP。应改为注册表/策略模式。

### C-7：死代码与工程基础设施缺失

**问题**：

- 无任何测试

## 3. 针对性优化建议（Actionable Advice）

### 3.1 C-1 + C-2：HybridizationWindow 异步化 + 缓存

**方案**：引入 `HybridizationWorker(QThread)` + 解析缓存，彻底消除主线程阻塞和重复 I/O。

```python
# ===== 新建 core/services/hybridization_worker.py =====

class HybridizationWorker(QThread):
    """后台解析两个 fragment，避免主线程阻塞。"""
    result_ready = Signal(object, object)   # (frag1_data, frag2_data)
    error_occurred = Signal(str, str)       # (error_type, message)
    progress = Signal(int)                  # 0-100

    def __init__(self, frag1_params, frag2_params, shared_cache=None):
        super().__init__()
        self.p1, self.p2 = frag1_params, frag2_params
        self._shared_cache = shared_cache or {}

    def run(self):
        try:
            self.progress.emit(10)
            data1 = self._parse_with_cache(self.p1)
            self.progress.emit(60)
            data2 = self._parse_with_cache(self.p2)
            self.progress.emit(100)
            self.result_ready.emit(data1, data2)
        except (FileTypeError, DbandError, ValueError) as e:
            self.error_occurred.emit(type(e).__name__, str(e))
        except Exception as e:
            self.error_occurred.emit("UnexpectedError", str(e))

    def _parse_with_cache(self, params):
        """优先查共享缓存，未命中才解析。"""
        fp, atoms, orbitals, spin = params
        cache_key = (fp, atoms, spin, tuple(sorted(orbitals or [])))
        if cache_key in self._shared_cache:
            return self._shared_cache[cache_key]
        energy, rho_up, rho_dn, rho_total, ef = DataLoader.load_spin_all(fp, atoms, orbitals=orbitals)
        result = (energy - ef, rho_up, rho_dn, orbitals, ...)
        self._shared_cache[cache_key] = result
        return result


# ===== hybridization_win.py 改造 =====

class HybridizationWindow(QMainWindow):
    def __init__(self, state, parent=None):
        ...
        self._parsed_cache = {}  # 本地解析缓存
        self._worker = None

    def _generate_plot(self):
        if self._worker and self._worker.isRunning():
            return  # 防止重复提交

        p1 = self._collect_fragment_params(self.frag1)
        p2 = self._collect_fragment_params(self.frag2)

        self.btn_plot.setEnabled(False)
        self._show_loading()

        self._worker = HybridizationWorker(p1, p2, self._parsed_cache)
        self._worker.result_ready.connect(self._on_data_ready)
        self._worker.error_occurred.connect(self._on_parse_error)
        self._worker.finished.connect(self._on_worker_finished)
        self._worker.start()

    def _on_data_ready(self, data1, data2):
        """后台解析完成 — 仅在主线程执行绘图（~10ms）。"""
        self._render_plot(data1, data2)

    def _on_theme_changed(self):
        """主题变更：仅重绘，不重新解析。"""
        if self._has_plot_data and self._cached_data:
            self._render_plot(*self._cached_data)  # 直接使用缓存数据
```

### 3.4 C-5：内存感知的 LRU 缓存

**方案**：从"按文件数"改为"按估算内存大小"淘汰。

```python
# models/app_state.py

class MemoryAwareLRUCache(OrderedDict):
    """按内存占用（而非文件数）淘汰的 LRU 缓存。"""

    def __init__(self, max_memory_mb: int = 512):
        super().__init__()
        self.max_memory = max_memory_mb * 1024 * 1024  # bytes
        self._current_memory = 0

    def __setitem__(self, key, value):
        if key in self:
            self._current_memory -= self._estimate_size(self[key])
            self.move_to_end(key)
        super().__setitem__(key, value)
        self._current_memory += self._estimate_size(value)
        while self._current_memory > self.max_memory and len(self) > 1:
            _, evicted = self.popitem(last=False)
            self._current_memory -= self._estimate_size(evicted)

    def __getitem__(self, key):
        value = super().__getitem__(key)
        self.move_to_end(key)
        return value

    @staticmethod
    def _estimate_size(value: dict) -> int:
        """估算缓存条目的内存占用（bytes）。"""
        total = 0
        for v in value.values():
            if isinstance(v, dict):
                for arr in v.values():
                    if hasattr(arr, 'nbytes'):
                        total += arr.nbytes
            elif hasattr(v, 'nbytes'):
                total += v.nbytes
        return total
```

### 3.5 C-6：DataLoader 策略模式重构

```python
# core/loader.py

class DataLoader:
    """统一加载接口 — 注册表模式，符合 OCP。"""

    _parsers: Dict[str, callable] = {}  # ftype -> parser_func

    @classmethod
    def register_parser(cls, ftype: str, parser_func):
        """注册新的解析器（插件扩展点）。"""
        cls._parsers[ftype] = parser_func

    @classmethod
    def load(cls, filepath, atoms, spin="total", orbitals=None):
        ftype = cls.detect(filepath)
        parser = cls._parsers.get(ftype)
        if not parser:
            raise FileTypeError(filepath)
        return parser(filepath, atoms, spin, orbitals=orbitals)

# 注册内置解析器
DataLoader.register_parser("vasprun.xml", parsers.parse_vasprun)
DataLoader.register_parser("DOSCAR", parsers.parse_doscar)
DataLoader.register_parser("VASPKIT PDOS", lambda fp, atoms, spin, **kw: parsers.parse_vaspkit(fp, spin, atoms_str=atoms, **kw))
```
